          Research project
          
AI Product Description Generator

          
A practical workflow for creating clearer, consistent product listings.

          
Abhishek Tiwari · 1338220   |   Biren Gohel · 1317182

        

        
Generate a draft from facts the seller provides. The first version sends the facts with each request — no model training, no catalog database search.

      


      

        

          
The catalog writing problem

          
What sellers haveWhat customers need

            
Raw attributes and notesA quick sense of fit and use

            
Different writing styles across SKUsConsistent voice across a range

            
Repeated manual draftingFast updates when products change

            
Search terms may be overlookedClear titles and descriptions

          

          
Human cost: a wrong material, size, compatibility statement or performance claim can mislead a buyer. Automation should remove blank-page work, not remove responsibility.

System architecture

        

          
SellerProduct facts, style, destination

          
Web UIForm validation, live preview

          
FastAPI logicValidate · normalize · prompt · provider adapter

          
LLM providerOpenAI · Gemini · Offline

          
Response checkParse JSON, required fields, claim guardrail

          
MongoDBgenerations · images · voices · logs

          
SellerEdit, approve, copy or export

        

        
Server-side responsibilities: provider keys stay out of the browser; the backend owns timeouts, bounded retries, safe errors, request limits and minimal logs.

      


      

        
What happens during one request

        

          
01Validate
Required fields, text length, allowed tone and export option

          
02Normalize
Trim whitespace and package the facts consistently

          
03Build prompt
Facts + tone rules + optional keyword + JSON schema

          
04Call model
Secure request with timeout and bounded retry

          
05Check response
Parse JSON; field types, required values, empty results

          
06Return draft
Field-by-field preview with copy and export actions

        

      


      

        

          
Limitations & safeguards

          
LimitationSafeguard in this build

            
Model may invent or overstate a benefitFact-only prompt + automatic unsupported-claim flags + human review

            
SEO wording cannot guarantee rank or trafficKeyword used naturally; overuse flagged; measure real outcomes

            
Provider latency, outages or cost varyTimeouts, limited retries, rate limit, latency logged in MongoDB

            
Tone may sound generic or inconsistentSaved brand voices with rules + examples; human editing

            
Export may not match every storefront schemaPlain / HTML / JSON / CSV exports; validate required fields

            
Product data can be sensitiveKeys server-side, STORE_INPUTS switch, delete from history

            
Schema checks structure, not truthReview gate before approval and export

            
Generated images are illustrationsFlagged on every image; must be compared with the real product

            
Image → text can misread a photoOnly visible details used; material/size marked “not verified”

            
Image → image may alter the productPrompt locks shape/colour/labels; reviewer confirms before use

            
Offline mode is template-basedClearly labelled; add an API key for model-quality output
